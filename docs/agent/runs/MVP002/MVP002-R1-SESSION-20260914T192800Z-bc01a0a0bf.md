## Goal

Remediate two Development Control architecture findings on PR 20 without
broadening MVP002: complete governed-gateway approval handling, and move live
connector health off the PostgreSQL write transaction.

## Scope completed

- `GovernedToolGateway` loads persisted workflow approvals through
  `ApprovalRepository.list_for_workflow`, converts them to `ApprovalRecord`, and
  passes them as `PolicyRequest.approvals`.
- `REQUIRE_APPROVAL` does not execute the connector and does not fail the task.
  It persists PENDING requirements via existing `ApprovalModel` /
  `ApprovalRepository`, sets task `AWAITING_APPROVAL` and workflow
  `APPROVAL_REQUIRED`, audits `APPROVAL_REQUIRED`, and returns a typed
  `AWAITING_APPROVAL` gateway outcome.
- Matching effective operation approvals resolve `ALLOW` through existing
  `PolicyEngine` / `match_operation_approval` rules. Dispatch intents bind the
  matching `approval_id`.
- Expired or mismatched approvals do not authorize execute.
- Live `binding.health()` runs only outside a write transaction (or an unexpired
  persisted `ConnectorHealthSnapshot` is reused). Fail-closed R2 health policy
  is unchanged. Dispatch intent is still recorded atomically before execute.
- Supervisor treats `AWAITING_APPROVAL` like parked so the interview loop does
  not mark the workflow failed.
- Additive legal transition `EXECUTION → APPROVAL_REQUIRED` so gateway-time
  approval wait is a legal workflow edge.

- Reused `ApprovalModel`, `ApprovalRepository`, domain `ApprovalRecord`,
  `match_operation_approval`, and `AWAITING_APPROVAL` / `APPROVAL_REQUIRED`.
  No second approval system.

  outside the write txn and persists the snapshot inside the write txn.

  PIVOT001 evaluates policy at gateway execute time, not only in `POLICY_CHECK`.
